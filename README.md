# SupplyGuard AI: Predictive Backorder Analytics

**Predicting backorder risks to support proactive inventory and supply-chain decisions.**

## Project overview
SupplyGuard AI is a machine-learning classification project that predicts whether a product may go on backorder. The goal is to help supply-chain and inventory teams identify potential risks early enough to investigate them.

The dataset is highly imbalanced, so accuracy alone is not a sufficient evaluation measure. This project compares models using precision, recall, and F1-score as well as accuracy.

## Dataset
The notebook expects a CSV named `Training_Dataset_v2.csv`.

The dataset is not included in this repository. Obtain it from the original course/project source or the dataset provider and make sure you have permission to use it. See [`data/README.md`](data/README.md) for setup instructions.

## Notebook workflow
1. Load and inspect the dataset.
2. Explore the data and target-class imbalance.
3. Split data into training and test sets using a stratified split.
4. Fit preprocessing steps using training data and apply the learned values to the test data.
5. Train and compare Logistic Regression, Decision Tree, Random Forest, and a tuned Decision Tree.
6. Evaluate the models using accuracy, precision, recall, F1-score, classification reports, and confusion matrices.
7. Review feature importance and discuss business implications and limitations.

## Evaluation and business interpretation
- **Recall** measures how many actual backorders the model detects.
- **Precision** measures how many predicted backorders are actual backorders.
- **F1-score** balances precision and recall.
- **False negatives** are missed backorders.
- **False positives** are alerts for products that do not go on backorder.

A high-recall model may help surface more potential risks, but low precision can create many false alerts. Model results should be regenerated by running the notebook; do not rely on old notebook outputs if the code or settings have changed.

## Limitations
- The target classes are highly imbalanced.
- False positives may create extra work for supply-chain teams.
- The model is a learning/portfolio project and should not be used for operational decisions without further validation, monitoring, and business review.
